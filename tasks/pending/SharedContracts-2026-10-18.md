# [GKMKB] Shared contracts (models, schemas, fixtures)

## What
Implement FlowRecord, Detection, Alert, HoneypotSession, Rule as pydantic models in contracts/, export JSON Schemas, add one valid and one invalid fixture each.

## Why
Every module codes against these. Nothing else can start without them.

## Acceptance Criteria
- [ ] Models match GkmkbSpec section 4 exactly
- [ ] JSON Schema files generated by a script
- [ ] Fixtures validate in pytest
- [ ] README in contracts/ explains change policy

## Steps
1. Read `docs/specs/GkmkbSpec.md` section 4.
2. Create `contracts/models.py` with pydantic v2 models: `FlowRecord`, `Detection`, `Alert`, `HoneypotSession`, `Rule`. Field names and types match the spec exactly.
3. Create `contracts/export_schemas.py` that writes JSON Schema files to `contracts/schemas/`.
4. Create fixtures in `contracts/fixtures/`: one valid and one invalid JSON file per model.
5. Create `contracts/test_contracts.py`: valid fixtures load, invalid fixtures raise.
6. Create `contracts/README.md`: the change policy (all owners review a contracts PR).
7. Run `ruff check .` and `pytest -q`. Open the PR.

Expected output: `pytest -q` passes; schemas exported; other owners can import `contracts.models`.
