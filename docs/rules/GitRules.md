# Git Rules
*Adapted from the Ojas GitRules for this team repo. Read before any commit, push or PR.*

## No AI footprint on GitHub (non-negotiable)
Each commit and PR must look like the author's own work. This overrides any default attribution the AI tooling suggests (`Co-Authored-By` trailers, "Generated with Claude Code" lines and similar).

### Commit messages
- Write in the author's own voice, plain English.
- No "Generated by Claude", "AI-assisted", "Claude Code:" or any AI attribution.
- No co-author lines of any kind.
- No sign-off lines unless asked.
- Conventional Commits preferred: `feat:`, `fix:`, `chore:`, `docs:`, `test:`.
- Keep them terse.

### Code comments
- No `// Added by Claude`, `# Generated by AI` or similar.
- Comments explain WHY, not WHO wrote it.

### PR descriptions
- Author's voice. No mention of AI assistance or agent authorship.
- No `🤖 Generated with…` footer.
- Focus on what changed and why.

### File headers
- No auto-generated headers mentioning AI tools. No agent timestamps or authorship metadata.

AI use is still disclosed once, in the project report (`docs/specs/GkmkbSpec.md` section 8 and `CONTRIBUTING.md`), not in git history.

## If you find AI footprint
1. Stop and tell the team lead (file, line, text).
2. Unpushed commits: amend or rewrite freely.
3. Already pushed: do not rewrite history or force-push without the lead's explicit yes.
4. Continue after cleanup.

## Branch strategy
- `main` is stable. Never commit to it directly.
- Working branches: `dev/<name>-<ticket>`, e.g. `dev/shivansh-dns-entropy`.
- Merge to `main` by PR only, one review plus green CI.

## Commit hygiene
- One logical change per commit.
- Never commit: `.env`, secrets, `node_modules/`, `__pycache__/`, `.venv/`, installed skills (`.agents/`, `.claude/skills/`), large pcaps.
- Check `.gitignore` before the first commit.
- `core.autocrlf=false` (the Docker images and scripts run on Linux).

## gh CLI
- `gh auth status` before any push.
- `gh pr create`, `gh pr merge` after review.
